# GPT助手模块扩展

GPT助手是统一产品，分支、书签及后续能力均属于其中的功能模块。共用 `launch-gpt-assistant.ps1` 启动流程、`inject.cjs` 客户端连接及本机服务，不为每个功能重复创建助手进程。

## 当前模块

| 模块编号 | 功能 | 源文件 | 客户端入口 |
| --- | --- | --- | --- |
| branches | 分支 | companion.js | window.__branchCompanion |
| bookmarks | 书签 | bookmarks.js | window.__bookmarkCompanion |

统一入口为 `window.__gptAssistant`，提供名称、版本、`listModules()`、`getModule(id)` 和 `dispose()`。现有客户端入口继续保留以兼容历史功能。

## 新功能接入

1. 在插件根目录新增独立的 `.js` 模块。模块在客户端页面执行，不依赖 Node.js 对象；创建的界面使用独立容器管理。
2. 向 `assistant.config.cjs` 的 `modules` 数组加入 `id`、`name`、`file` 和 `global`。编号须唯一；`file` 指向根目录下的 `.js` 文件；`global` 指向模块公开的 `window` 属性。
3. 如依赖已有模块，用 `dependsOn` 声明，并将该模块放在依赖模块之后。加载器会校验编号、文件名及依赖顺序。
4. 模块入口提供 `dispose()`，负责移除界面、事件监听器、观察器和定时器。模块代码须允许重复加载。GPT助手按加载顺序初始化，按相反顺序卸载。
5. 通过 `window.__gptAssistant.getModule(id)` 使用已有模块。初始化时依赖模块已存在，也可使用表中的兼容入口；统一入口在全部模块加载后建立。
6. 新功能如需文件存储或系统能力，在 `inject.cjs` 中增加明确的绑定与记录校验，存储独立命名，并在 `.gitignore` 中排除私人数据。不要直接改写其他模块的存储键或记录格式。
7. 修改模块清单、启动器或后台程序后重新连接GPT助手；已有模块的 `.js` 文件仍可热更新。更新产品版本时同步 `package.json` 和模块公开版本。

## 兼容与验证

保留现有 `branch-companion.v1`、`branch-companion.bookmarks.v1` 存储键、记录文件及外部链接格式。产品更名不迁移这些数据；后续确需迁移时提供显式兼容和恢复路径。

运行 `npm run check`、`npm test`，并在真实客户端检查新模块交互、热更新、重新连接及现有分支和书签是否正常。记录文件、原文片段和账号资料不进入 Git 提交。
